WXL remote player texture-item recolor — RE gap analysis
Date: 29/07/2026

User observation (confirmed by logs)
  Self player: recolor on TextureComponents works reliably.
  Other players: same server PUSH payload, tint sometimes applies once then
  model/face corrupts — or never stabilizes.

Logs proved (debug-615e3b.log)
  - PUSH/NoteEquip/ApplyOwnerTint data is CORRECT on observer (entry, displayId,
    mode, stems match plate_pvppaladin Chest_TU/TL).
  - remote_tint + overlay_ok fires on ForceOwnerBodyRebuild — tint path works.
  - Corruption follows: paste hooks with ownerLow=0, TextureCache ptr reuse
    between nearby players (paladin/shaman cross-assign).

Conclusion: NOT a wrong server packet. The gap is CLIENT-SIDE render identity.

----------------------------------------------------------------------
Current architecture (WarcraftXL GearRecolor.cpp) — SELF-CENTRIC
----------------------------------------------------------------------

Local self:
  hkRenderPrep: model == LocalPlayerBodyModel() → allowed, prepOwner=self
  IsPasteTintAllowed: prep == OwnerBodyModel(self) — TRUE (same pointer)
  TryHslForComponentTexture: g_prepOwnerGuid or ActiveOwnerGuid fallback
  g_slotHsl holds committed tint

Remote observer:
  hkRenderPrep: only allowed if BodyModelOwnerGuid(model) OR hasTint cache
  IsPasteTintAllowed: prep MUST equal OwnerBodyModel(remote) — OFTEN FALSE
    because ComponentModel(component) != unit root model (ResolveObject+0xB4)
  g_remoteTints separate map; ForceOwnerBodyRebuild to apply
  FindOwnerCharComponent: hunts CharComponent where component.model == unit body

This is a bolt-on remote path on top of a self-player paste hook design.

----------------------------------------------------------------------
Archive reference (_wxl-gear-recolor-archive) — UNIFIED PLAYER PATH
----------------------------------------------------------------------

File: DBC_Tool/_wxl-gear-recolor-archive/src/GearRecolor.cpp

Key differences:
  1) PrepOwnerScope (thread_local) for EVERY non-NPC RenderPrep
     owner = OwnerFromBodyModel(model) — not special local branch
  2) Unified g_tints[owner][slot] — no g_slotHsl vs g_remoteTints split
  3) OwnerFromBodyModel:
     - self: ModelIsUnderRoot(model, localBody)
     - remote: g_modelOwner cache + TintedOwners() scan + ResolveUnitModel
  4) QueueRepaste(owner) + RepasteOwnerNow — throttled, one owner/frame
  5) hkRenderPrep NEVER denies paste window for tinted nearby players
  6) Paste hook uses CurrentPrepOwner() — always set during RenderPrep

This matches the user's hypothesis: we need the SAME owner-resolution path
for all player bodies, not a second-class remote Force-rebuild hack.
